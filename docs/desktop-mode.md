# 桌面 DSH 同进程模式

当前源码默认 `execution_backend=desktop`，连接 DSH.app 正在使用的本机后台，不启动独立 headless Harness，不覆盖桌面配置。

桌面模式与旧兼容模式共用本仓库已有的 Ponytail 七步最小实现规则：先判断必要性，再依次考虑复用、标准库、原生特性、已有依赖、单行解和最小实现。Codex 侧保留精简上下文、goal 仅写目标和按差异验收等 token 管控规则。

## 日常使用

在 Codex 中启用 `deepseek-delegate` Skill 并说明需求即可。Codex 自动拆解任务、委派、读取结果、审核、返工与应用改动。监控入口仍为 `leadseek activate`，同一 Codex 任务不会反复打开监控，页面保留手动刷新。

下发任务时先检查本机服务身份。已有 DSH 服务直接复用；没有服务则在后台打开正常的 DSH.app，等待最多约 30 秒就绪。未安装客户端、端口由其他程序占用或启动失败时明确报错，不偷偷切换成另一套 Harness。

任务在原项目对应的 DSH 工作区创建 `Codex · 任务名称` 原生会话，可在 DSH 界面查看。CLI 回执记录实际 session_id、后台 PID、Harness 版本、模型及思考强度，无需为日常委派手动打开窗口。

## 会话与插件

下发、公开会话消息、工具调用与结果、父子 agent 状态、已报告的 token 用量均通过本机 HTTP 接口读取，不截图、不模拟点击。认证信息只保留在内存，不输出或写入任务日志。隐藏思考和 system/developer 指令不展示。

模型、思考强度、Agent 预设、插件、技能和权限沿用 DSH 原配置。DSH 自主选择已启用且当前预设可用的插件、工作流、子 agent 或智能体团队。任务默认省略 `subagents` 或设为 null；只有明确需要限制时才给整数。插件可用不表示每次都应调用全部插件，也不保证未安装、未启用或未完成配置的插件可用。

## 审核与边界

工具先复制必要文件到暂存目录，要求 DSH 第一工具切换到该目录，完成后检查修改范围。Codex 审核差异和测试，再通过 `leadseek apply` 应用；原项目已变化时拒绝直接覆盖。这是工作范围约束与事后检查，不是操作系统级隔离。

超时或连接异常只尝试取消当前任务，不关闭共享 DSH 后台或其他会话。完整公开记录留在本机 `.state/runs/`；监控 token 为已采集事件，缺失就是未知，不等于账单核算或节省比例。继承 Max 等设置也会继承相应用量和耗时。

## 安装和兼容

已有 DSH.app 时，当前源码的桌面安装分支仅接入 CLI/Skill，不再安装另一套 Harness，也不重新输入桌面已管理的密钥。新 Mac 仍需安装并登录 DSH.app；当前工具不会自行下载桌面客户端。

旧 `execution_backend=headless` 只作为明确选择的兼容模式保留。旧配置中的 `model`、`reasoning_effort`、运行时版本和预算插件仅用于该模式，不控制桌面 DSH。桌面默认地址为 `http://127.0.0.1:3080`，可在 `config.local.json` 覆盖为本机地址；远端地址会被拒绝。
